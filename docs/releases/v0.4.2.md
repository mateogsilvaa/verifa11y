# verifa11y 0.4.2

A documentation and packaging release. Nothing changes in how pages are audited, patched or verified.

```sh
npx verifa11y install-browser       # once: the headless Chromium it renders with
npx verifa11y audit page.html --out findings.json
npx verifa11y fix findings.json --verify --strict --out patches
git apply patches/verifa11y.patch
```

For AI agents, the MCP server: `claude mcp add verifa11y -- npx -y verifa11y-mcp --root .` (any MCP host: command
`npx`, arguments `-y verifa11y-mcp --root <project>`).

## What's new

- **A website**: https://mateogsilvaa.github.io/verifa11y/. It shows the verifier at work on a demo page, with install
  steps for every tool it supports.
- **A shorter README.** It now opens with the problem, a quick start and the six checks. The detailed sections live in
  [docs/](https://github.com/mateogsilvaa/verifa11y/tree/v0.4.2/docs), word for word.
- **Better npm pages.** `verifa11y` shows a banner and links to the new docs. `verifa11y` and `verifa11y-mcp` have
  fuller descriptions and keywords, so they are easier to find.
- **Project files**: a [security policy](https://github.com/mateogsilvaa/verifa11y/blob/v0.4.2/SECURITY.md), a citation
  file, a Dependabot configuration that leaves axe-core and Playwright pinned, and a feature request template.
- The GitHub Action's cache step uses `actions/cache@v6`.

verifa11y does not guarantee WCAG conformance. "Verified" means the automatic checks found the violation gone and
nothing else worse; every patch still needs a person to review it.

Full changelog: [CHANGELOG.md](https://github.com/mateogsilvaa/verifa11y/blob/v0.4.2/CHANGELOG.md).
